# План: Переделка интернет-магазина под ТЗ

**Цель:** Привести существующий Rails-проект в соответствие с ТЗ на онлайн-магазин розничной торговли одеждой.
**Ветка:** `new/market`
**Стек:** Ruby on Rails 8.1, PostgreSQL, Tailwind CSS, Devise, Pagy
**Подход:** Работа по этапам (Планирование → Создание → Тестирование). Регулярные коммиты.

---

## Этап 1: Переход на Devise + роли пользователей

**Задачи:**
1. Добавить `devise` и `letter_opener` в Gemfile, установить.
2. Сгенерировать Devise для User. Создать миграцию:
   - Переименовать/добавить поля: `encrypted_password`, `reset_password_token`, `reset_password_sent_at`, `remember_created_at`.
   - Добавить `role` (integer, enum: customer=0, manager=1, admin=2), default: 0.
   - Удалить старое `password_digest`.
3. Удалить кастомную аутентификацию:
   - `SessionsController`, `RegistrationsController`
   - Вьюхи `sessions/new`, `registrations/new`
   - Методы `current_user`, `require_login` из `ApplicationController`
4. Настроить Devise views (регистрация, вход, восстановление пароля) с Tailwind-стилями.
5. Настроить `letter_opener` для development (восстановление пароля).
6. Обновить `routes.rb` (убрать кастомные auth-роуты, добавить `devise_for`).
7. Обновить все вьюхи и контроллеры: заменить `current_user` → `current_user`, `require_login` → `authenticate_user!`.
8. Обновить `ProfilesController` — редактирование профиля через Devise или отдельный контроллер.
9. Протестировать: регистрация, вход, выход, восстановление пароля.
10. **Коммит.**

**Критерии приёмки:**
- Регистрация/вход/выход работают через Devise.
- Восстановление пароля отправляет письмо (letter_opener).
- Все существующие страницы доступны только авторизованным пользователям, где требуется.

## Этап 2: Модели Categories, Brands и обновление Products

**Задачи:**
1. Создать модель `Category` (name:string) + миграция.
2. Создать модель `Brand` (name:string) + миграция.
3. Обновить `Product` миграциями:
   - Добавить `sku` (string, unique, index).
   - Добавить `discount` (integer, default: 0) — процент скидки.
   - Добавить `status` (integer, enum: draft=0, published=1, archived=2), default: 0.
   - Добавить `average_rating` (decimal, default: 0) — кэш среднего рейтинга.
   - Добавить `in_stock` (boolean, default: true).
   - Добавить `category_id` (FK), `brand_id` (FK).
   - Удалить старое строковое поле `category`.
   - Удалить `compare_at_price` (логика скидки переходит на `discount`).
   - Перейти с `has_one_attached :image` на `has_many_attached :images`.
4. Обновить модель `Product`:
   - `belongs_to :category`, `belongs_to :brand`.
   - `has_many_attached :images`.
   - Валидации: `sku` уникален, `name`, `price`, `category`, `brand` обязательны.
   - Метод `final_price` = price * (1 - discount/100.0).
   - Метод `on_sale?` — discount > 0.
5. Обновить `CatalogController` — фильтрация по `category_id`, `brand_id`.
6. Обновить `seeds.rb`:
   - Создать категории (Футболки, Джинсы, Куртки).
   - Создать бренды (ForestWalk, DenimPro и т.д.).
   - Привязать продукты к категориям и брендам, добавить SKU, discount, статус published.
   - Прикрепить несколько изображений (или хотя бы по одному).
7. Протестировать: каталог отображается, фильтры работают, товары создаются с новыми полями.
8. **Коммит.**

**Критерии приёмки:**
- Таблицы categories и brands созданы.
- Продукты имеют SKU, скидку, статус, наличие, привязку к категории и бренду.
- Каталог отображает товары с новой структурой.
- Seeds заполняют базу корректно.

## Этап 3: Каталог — поиск, фильтры, сортировка, пагинация, лендинг

**Задачи:**
1. Добавить `pagy` в Gemfile, настроить хелпер.
2. **Поиск:** скоуп `search(query)` — по `name` ILIKE и `sku` ILIKE.
3. **Фильтры в каталоге:**
   - По категории (чекбоксы/выпадающий список).
   - По бренду (чекбоксы).
   - По размеру (чекбоксы — используем `sizes` массив).
   - По цвету (чекбоксы/список уникальных цветов).
   - По цене (min/max поля).
   - По наличию (чекбокс `in_stock`).
4. **Сортировка:**
   - По цене (возрастание/убывание) — учитывать `final_price`.
   - По популярности (по количеству продаж в `order_items`).
   - По новизне (`created_at desc`).
   - По скидкам (`discount desc`).
5. **Пагинация:** применить Pagy к каталогу.
6. **Главная страница (лендинг):**
   - Популярные категории (ссылки с иконками/картинками).
   - Блок акций/скидок (товары с `discount > 0`).
   - Адаптивная вёрстка (Tailwind).
   - Отзывы и рейтинги на карточках товара (пока заглушка или реальный rating, если этап 4 уже сделан).
7. Обновить `CatalogController#index` и вьюхи.
8. Протестировать: все фильтры, сортировки, поиск, пагинация работают корректно.
9. **Коммит.**

**Критерии приёмки:**
- Пользователь может искать товары по названию и артикулу.
- Фильтры по категории, бренду, размеру, цвету, цене, наличию работают.
- Сортировка по цене, популярности, новизне, скидкам работает.
- Пагинация отображается.
- Главная страница адаптивна и показывает категории + акции.

## Этап 4: Карточка товара, отзывы, избранное, рекомендации

**Задачи:**
1. **Отзывы:**

   - Вьюха на странице товара: список отзывов, форма добавления (для авторизованных).
   - Пересчёт `average_rating` продукта при создании/удалении отзыва.
2. **Избранное:**

   - Контроллер `FavoritesController` (create, destroy, index).
   - Кнопка "В избранное" на карточке товара и в каталоге.
   - Страница избранного в личном кабинете.
3. **Рекомендации:**
   - Скоуп/метод `similar_products` — товары той же категории, исключая текущий, limit 4.
   - Отображение на странице товара.
4. **Карточка товара:**
   - Обновить `ProductsController#show` — убрать редирект, нормальная страница.
   - Галерея изображений (если несколько — простой переключатель).
   - Отображение: артикул, название, категория, бренд, размеры, цвет, цена, скидка, наличие, рейтинг, описание, характеристики.
   - Кнопка "Добавить в корзину" с выбором размера.
5. Протестировать: отзывы создаются, рейтинг пересчитывается, избранное работает, рекомендации показываются.
6. **Коммит.**

**Критерии приёмки:**
- На странице товара отображаются все поля из ТЗ.
- Авторизованный пользователь может оставить отзыв с рейтингом 1-5.
- Средний рейтинг обновляется.
- Пользователь может добавлять/удалять товары из избранного.
- Показываются похожие товары (та же категория).

## Архитектурные решения

- **Аутентификация:** Devise (замена custom auth).
- **Авторизация:** Проверка ролей вручную (`user.admin?`, `user.manager?`) в контроллерах.
- **Админка:** Собственные контроллеры в namespace `Admin`, без гемов.
- **Поиск/фильтры:** Скоупы + LIKE, без сторонних гемов.
- **Пагинация:** Pagy (лёгкий, быстрый).
- **Почта:** Letter Opener в development.
- **Остатки:** Boolean `in_stock` (не количество по размерам).
- **Скидка:** Integer `discount` (процент), цена рассчитывается как `price * (1 - discount/100.0)`.
- **Изображения:** Active Storage `has_many_attached :images`.
- **Рейтинг:** Кэшируемое поле `average_rating` в products, пересчитывается при изменении отзывов.

## Возможные риски

- Переход с custom auth на Devise может затронуть много файлов. Нужно внимательно проверить все ссылки на `session[:user_id]` и `current_user`.
- Изменение структуры products (удаление строкового category, добавление FK) потребует обновления всех вьюх и контроллеров каталога.
- Нужно следить, чтобы Docker-окружение оставалось рабочим после добавления новых гемов.
